# Motion Atlas — 代码动效成片

Turn a request like 「挑 8 款暗黑科技风做 40 秒开场」 into a finished MP4. Every frame is generated by code: no footage, no stock assets.

## 0. Get the kit

The code lives in the **motion-atlas** kit (`app/`, `tools/`, `STYLES.md`, `README.md`).

1. Look for the kit in this order:
   - a `motion-atlas/` folder or `motion-atlas.zip` in the working directory or among the user's uploads;
   - otherwise ask the user for the zip or the repo link.
   - If neither exists, go to section 6.
2. Install dependencies:

   ```bash
   pip install playwright numpy scipy pillow
   python3 -m playwright install chromium
   ```

   You also need `ffmpeg`. If the environment already ships Chromium, point Playwright at it instead of installing.
3. Rendering needs a real shell with Chromium and ffmpeg. In a chat without code execution, you can only publish `app/gallery.html` as a live page. Say so before promising an MP4.

## 0.5 Which mode does the user want?

- **Full film** ("做一支视频 / 合集 / 开场"): follow sections 1–4.
- **Single clip to drop into their own edit** ("只要彩墨那段 / 导出素材 / 插进我的视频"):
  - run `python3 tools/clip.py KEY [--dur S] [--vertical] [--loop] [--png]`;
  - the output is art only: no text panel, no HUD, no audio;
  - `--vertical` crops 1080×1920 around the subject; adjust `--cx` if the subject sits elsewhere;
  - preview the key first with `tools/preview.py style KEY 1 4 7`, then deliver `out/clips/KEY.mp4`.
  - Several clips are fine: run one per key.
- **Live on a web page:** load the `app/` scripts and call `renderST(index, lt)` each frame. `docs/index.html` is a working example.

## 1. Settle the brief, then pick styles

Ask at most one short question, and only if the answer changes the plan. Things that matter:
- **Purpose:** showcase, product opener, or social post.
- **Length:** 4 s per style for punchy social cuts, 6 s for showcase.
- **Mood:** dark / light / mixed.
- **Brand colour.**
- **Count:** 8–15 styles reads well.

Pick from `STYLES.md`. Build the order for rhythm:
- **Open** on the strongest transformation, e.g. `SATURNX` (eclipse → sunrise flare) or `COLORINK`.
- **Alternate** dark and light scenes, and calm and kinetic ones.
- **Never** put two near-identical scenes back to back, e.g. two data charts or two spinning tunnels.
- **Close** on something luminous: `NEBULA`, `GLASS`, `AURORAX`.

Proven high-impact picks:
- **Spectacle:** `SATURNX`, `COLORINK`, `GLASS`, `NEBULA`, `AURORAX`
- **Kinetic satisfaction:** `SPLITFLAP`, `DOMINO`, `STAMPS`, `MEMPHIS`, `TERRACE`
- **Premium still life:** `VASE`, `CAIRN`
- **Mathematical:** `STRINGART`, `MOBIUS`, `PENROSE`
- **Data:** `CANDLES`
- **Depth:** `STAIRWELL`

Avoid as hero shots (they read static): `ORBITAL`, `WINDMAP`, `ISOTYPE`, `THERM`.

## 2. Configure the film

Edit `app/scenes.js`:
- **`PICK` rows:** `[KEY, 'dark'|'light', 'R,G,B' accent, 'SHORT TAGLINE', 'HUD LINE · TECH NUMBERS']`
- **`PAL`:** 3–5 hex swatches per key, shown under the panel.
- **`SCRIM`:** an RGB string for busy or light scenes, so the left text stays readable.
- **`ZOOM`:** a slow push-in, 0.03–0.1, for scenes that need extra motion.
- **`dur`:** per-key seconds, default 6. Animations are time-compressed, so a 4 s scene still completes its full arc.
- **`SFX`:** sound accents in scene-local time `lt` (0..8), as `[lt,'boom'|'thud'|'click'|'pop'|'whoosh'|'flap'|'shimmer']` or `['run', type, lt0, lt1, count]`. Put hits on the visual beat: a flare, a landing, each tile falling.

Edit `app/meta.js`. Each key gets `[desc, [3 tech tags], 'English work title', '中文作品名']`. Copy rules, learned from user feedback:
- **The description explains the style itself:** what it is, where it is used commercially, why it works. Do not narrate how the frame forms.
- **Tech tags** are short noun phrases, e.g. `光线步进`, `域扭曲`, `减色混合`.
- **Work titles** are evocative and two to four words, e.g. `Ring of Fire「火环」`. Avoid plain or tacky names.
- **No line may start with punctuation;** `wrapCJK` already enforces this. Keep descriptions to about 60 Chinese characters so they fit 3 lines at 530 px.

Intro and outro text live in `app/bookend.js`: the title, `第二弹`, and the `VOL.` line. The intro is a rapid montage, one 0.19 s cut per scene with flash and push, then a mosaic and the title. The outro is a thumbnail grid. Do not replace the montage with a list of names; the user explicitly preferred the montage.

## 3. Check before rendering (always)

```bash
python3 tools/thumbs.py
python3 tools/preview.py scenes      # 3 frames per scene -> out/preview/sheet.jpg
```

Look at the sheet yourself (Read the image). Fix before rendering:
- **Text panel collides with the subject.** The subject must sit right of x≈760 px. Shift it with lens shift (`cam3(..., [260,0])`, `sx` in `rmStyle`) or add a `SCRIM`.
- **A scene barely changes** across its 3 frames. Add a camera move, a build-up (things drop in or rise up), a light sweep, or shorten it to 4 s. The user rejects static scenes ("没有动感张力").
- **Stepped motion reads as stutter.** Quantised animation (`Math.floor(lt*8)` stripes) looks choppy. Use continuous phases.
- **Overlapping pigments turn black.** In subtractive mixes, weight by the dominant pigment rather than summing.
- **Physical motion runs backwards.** Check that cause → effect reads correctly. Domino tiles must tip toward the next unfallen tile; the original bug was the opposite.
- **Wrong frames in raymarched shaders.** `pow(negative, n)` is undefined in GLSL; write `(x)*(x)*(x)`.

## 4. Render and deliver

```bash
python3 tools/render.py 2        # thumbs -> music -> parallel chunks -> concat -> mux -> share copy
```

- Raymarched scenes cost 2–15 s per frame on CPU, so a 90 s film takes 1–2 h. Run it in the background and watch the logs.
- To re-render only changed scenes: `python3 tools/render.py 2 <chunk ids>`. Chunks are 3 s each, chunk = floor(seconds / 3).
- Deliver `out/film_share.mp4`; it is about 2.4 Mbps and under 30 MB for 90 s. Mention that `out/film_master.mp4` exists.
- After delivering, ask which scene number feels slow or weak. Users answer by index ("第五个").

## 5. Visual rules (non-negotiable)

- **Depth** comes from wide-angle perspective, converging lines and layering, never from depth-of-field blur.
- **Composition:** no dead-centre compositions. Use diagonals and flow, with the subject weighted right so the text panel sits left.
- **Palette:** use considered, commercial palettes. Avoid tacky motifs (5-point stars, black + hot pink).
- **Timing:** roughly 4–6 s per style. Every scene needs a visible change between its first and last second.
- **Sound:** a steady groove plus hits synced to on-screen events; the user loved hits that land exactly on a visual burst. Do not replace the music with busy per-scene sound design; that was rejected.

## 6. Writing a new style (or working without the kit)

All styles push into a list `ST` with `{key, cn, en, cat, desc, render(lt)}` where `lt` runs 0..8. There are three authoring paths, all in `app/`:

- **`shaderStyle(meta, glslFragment, postFn)`:** a full-screen fragment shader. Uniforms are `T` (lt) and `R` (resolution), with helpers `n3`, `fbm`, `rot`. Best for fluids, nebulae, light and fields.
- **`st2D(meta, lt => {...})`:** Canvas 2D on `X` (1920×1080). Use `cam3(eye, target, fov, roll, [shiftX, shiftY])` and `line3` for true perspective, painter-sort quads for 3D solids, and `grain(X, a, mode)` for film grain. Best for typography, graphic design, mechanical motion and data.
- **`rmStyle(meta, {map, pal, bg, ro, ta, fov, sx, L, key, amb, spec, shin, fog, pre})`:** raymarched SDF still life with soft shadows, AO and ACES. Animate through `T` inside `ro` and `map`.

If the kit is unavailable, rebuild the same architecture:
- a page exposing `window.render(t)` and `window.TOTAL`;
- Playwright screenshots piped into ffmpeg;
- a numpy-synthesised 120 BPM track with hits at scene starts.

Then write each style from its one-line description in `STYLES.md`.
